# Обязательные правила Codex

## Проверка через Graphify

1. Перед изменением существующего кода использовать Graphify для анализа связанных функций и файлов.
2. Проверять возможные последствия изменений через graphify_impact.
3. Находить связанные тесты через graphify_tests_for.
4. Если Graphify недоступен или индекс неполный, сообщить об этом. Не выдавать непроверенные зависимости за факты.
5. Не изменять утверждённую функциональность без разрешения владельца проекта.
6. После изменений запускать доступные сборки и тесты.
7. Сообщать результаты проверок, ошибки и ограничения.
8. Не объявлять работу завершённой без подтверждённых результатов проверок.

## Права на изменения

Владелец проекта утверждает функциональность.
Не выполнять дополнительные изменения без его разрешения.

## Актуальная база БУСА-1М №001 (23.11.2026)

Перед любыми изменениями прошивки прочитать [утверждённую успешную сборку, распиновку, телеметрию и статус испытаний](docs/BUSA_BASELINE_2026-11-23.md).
Установленная версия из телеметрии не подтверждена как идентичная исходникам `main` или старым BIN. Не подменять утверждённую базовую сборку. Проверять исходники/двоичные файлы перед сборкой и прошивкой.

## Устав разработки БУСА-1М №001 — утверждён 24.11.2026

Обязателен для чата проекта и Codex. Владелец проекта утвердил последовательность разработки 24.11.2026. Исходный документ: [BUSA_workflow.md на Google Drive](https://drive.google.com/file/d/18cj7VgPS53PqlTgPB4pujfirVj46Ka2r/view). Устав не изменять без согласия владельца проекта. Применять при каждом задании в пределах согласованного объёма работ.

1. **Чат проекта + GitHub + Notion** — получить утверждённое ТЗ, базовую версию, ограничения и исходники; сверить источники.
2. **Google Drive + Google Sheets** — изучить документацию, телеметрию и результаты предыдущих проверок при необходимости.
3. **Graphify + Superpowers** — исследовать зависимости, воспроизвести ошибку, определить причину и область изменения.
4. **Context7 + официальная документация** — проверить API, библиотеки, версии и совместимость.
5. **Superpowers + Anti-Slop Engineering** — составить план, критерии приёмки и тесты; не менять утверждённую функциональность без разрешения. Согласовать общий контракт связи прошивки и приложений, если он затронут.
6. **Figma** — сверить утверждённый дизайн; при изменении интерфейса согласовать макет до реализации.
7. **Чат проекта / Codex + Anti-Slop Engineering** — реализовать только согласованные изменения: прошивка ESP32-S3 N16R8, Android-приложение, локальное приложение. Проверить общий API; независимые изменения можно выполнять параллельно. Не изменять компоненты, которых задача не касается.
8. **Superpowers + Graphify + Daybreak** — проверить изменения, регрессионные тесты, совместимость и безопасность; явно отметить недоступные проверки.
9. **GitHub Actions** — собрать нужные компоненты из фиксированных коммитов, проверить логи, тесты и артефакты. При ошибке вернуться к диагностике; не выдавать результат за готовый.
10. **GitHub — комплект для установки** — USB_MERGED.bin (объединённый образ, адрес записи по конфигурации), OTA.bin (образ приложения, проверка совместимости разделов), APK (подписанный, совместимый с обновлением), локальное приложение (формат по архитектуре проекта), SHA-256, журнал сборки, версия, инструкция и ссылки на реальные файлы. .ino — по запросу. Если локальное приложение встроено в прошивку, отдельный установщик не требуется.
11. **Реальное устройство + Android + локальный интерфейс** — проверить USB и OTA, запуск, связь, сохранение функций и совместимость приложений в пределах задачи. При сбое вернуться к диагностике.
12. **Чат проекта + GitHub + Notion / Google Drive** — зафиксировать подтверждённые результаты. Только после необходимых проверок и решения пользователя обозначить версию рабочей; сохранить предыдущую рабочую версию.

Обязательное правило: успешная сборка не равна подтверждённой работе на оборудовании. Плагины применяются по доступности и назначению. Этот регламент не подтверждает наличие конкретных CI-сценариев или формата локального приложения в текущем репозитории.
