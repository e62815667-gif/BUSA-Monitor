# BUSA UI14 — меню и разделы без перелистывания

Дата: 14.11.2026. База: UI13, коммит `21970fa`.
Версия: `14v9-N16R8-RM-CALC4-WIFI1-UI14-20261114`.
Плата: ESP32-S3 N16R8, Arduino ESP32 2.0.17, Flash 16 MB,
OPI PSRAM, QIO, `app3M_fat9M_16MB`.

В UI13 автоматическая разбивка была убрана только из калибровки и Wi-Fi.
UI14 удаляет весь механизм презентационных страниц из локального приложения:
нет счётчика `1/2`, нижних кнопок «Далее/Назад», скрываемых частей формы
или разрезания диагностического текста на отдельные листы.

Все девять пунктов настроек видны вместе, в прежнем порядке:
Температура, Wi-Fi, Экран, Google, Bluetooth · RainMaker, Обновление ПО,
Журнал событий, Диагностика, О системе. Высота строк зависит от доступной
высоты окна. В коротком горизонтальном окне применяется сетка из двух
колонок с тем же порядком элементов.

Температуры и вода/отбор компактно помещаются в обычное окно телефона.
Если раскрытая форма, журнал или отчёт длиннее окна, содержимое доступно
через обычную прокрутку внутри соответствующей панели. Шапка и нижняя
навигация остаются на месте; элементы и текст не удаляются и не делятся
на дополнительные страницы.

Калькулятор, выбор сети Wi-Fi, калибровка и рисунок сохраняют изменения UI13.
Основной скрипт локального приложения и файлы калькулятора сохранены
по контрольным суммам. Распиновка, физический TFT, клавиатура, датчики,
выходы, NVS, RainMaker, Google и OTA не переназначены.

## Проверки

`tests/test_ui14_viewport.py` проверяет восемь размеров:
320×568, 375×600, 375×667, 390×636, 390×744, 390×844,
430×932 и 844×390. Проверяются одновременно все девять пунктов,
их порядок и границы, переход в каждый пункт/обратно, все разделы,
все вкладки диагностики, длинный журнал и копирование полного отчёта.

Старое поведение воспроизводится командой:
`BUSA_TEST_BASELINE=21970fa python tests/test_ui14_viewport.py`.
Она завершается ожидаемой ошибкой: в старом меню видны не все девять пунктов.

Проверки UI13, шапки/навигации, живого опроса, Wi-Fi и калькулятора
сохраняются. Снимки тестов содержат только HTTP-имитацию показаний.
Локально используется Chromium; WebKit не установлен, его запуск предусмотрен
в CI. Физический iPhone и ESP32 при сборке не используются.

## Установка

- `BUSA_UI14_APP_OTA.bin` — Настройки → Обновление ПО в локальном приложении.
- `BUSA_UI14_USB_MERGED.bin` — запись через USB с адреса `0x0`.

Для сохранения текущих настроек предпочтительно OTA. USB merged может
перезаписать обычную NVS. Полный erase не нужен; раздел `fctry` RainMaker
в компактный USB-образ не включается.

Пакетирование: `ci/package_ui14.py`; проверяются заголовок ESP32-S3,
размеры/разметка, checksum/hash и точное равенство APP в обоих образах.
