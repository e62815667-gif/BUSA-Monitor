## Интерфейс

В приложении и в основном цикле физического БУСА шесть разделов:
Главная → Температуры → Отбор → Графики → Калькулятор → Настройки.
События и Диагностика находятся в Настройках. На физическом экране ENT открывает выбранный пункт, ESC возвращает в родительский список. Прежние настройки температуры, Wi-Fi, экрана, Google и About сохранены.

Графики на обоих экранах: единая шкала 0–125 °C, четыре цветные линии с легендой, вкладки Температуры / Расход / Питание, периоды 1/6/12/24 часа. На физической клавиатуре UP/DOWN выбирает вкладку; ENT переключает выбор на период, UP/DOWN меняет период; ESC возвращает выбор вкладки. LEFT/RIGHT переключают основные разделы.
История — минутные точки реальных температур за последние 24 часа в PSRAM, только с момента включения. Пропуски и отключённые датчики остаются пробелами. Перезапуск очищает RAM-историю. Для памяти используется отдельная буферная область примерно 29 КБ; при невозможности выделить её график остаётся без измерений. Старый /api/graph-history сохранён, новый /api/chart-history?hours=1/6/12/24 обслуживает новый график.
Датчика отбора и измерения питания в этой прошивке нет; их вкладки явно показывают отсутствие данных. Импульсы охлаждающей воды не выдаются за отбор жидкости. Никаких тестовых значений в прошивке нет.

Внизу Главной — роли выходов в исходном порядке: ТЭН откл. / Кран закрыт / Кран открыт / Авария. Подсветка соответствует фактическому программному состоянию выхода (sound_on / busaSoundActive), без нового управления оборудованием. Нет обратной связи о физическом положении крана или состоянии ТЭН. На отключённом браузере индикаторы переходят в «Нет связи». В диагностике видимая группа называется «Блок реле».
Калькулятор оформлен в общей синей теме, результаты выровнены, длинные условия расчёта свёрнуты в отдельную заметку. Формулы, единицы, расчёты, ошибки и сохранение ввода не изменены.
Один заголовок BUSA MONITOR, без заводского номера, время ЧЧ:ММ. Серийный идентификатор телеметрии и регистрация RainMaker не изменены.

## Сборка и файлы

Arduino CLI 1.3.1, официальный ESP32 Arduino 2.0.17, gcc esp-2021r2-patch5-8.4.0; те же библиотеки и параметры N16R8/OPI/QIO/USB, что UI5 (README_UI5.md).
В этой среде официальный core установлен вручную как espressif:esp32:esp32s3; на стандартной установке использовать esp32:esp32:esp32s3.
Пакетирование: python ci/package_ui6.py --build-dir <out> --core-dir <esp32-2.0.17> --esptool <esptool.py>.

Два отдельных файла:
- BUSA_N16R8_RM_CALC4_WIFI1_UI6_APP_OTA.bin — локальная форма обновления по Wi-Fi. Предпочтительный вариант для сохранения настроек.
- BUSA_N16R8_RM_CALC4_WIFI1_UI6_USB_MERGED.bin — запись через USB от 0x0. Не выбирать в OTA-форме. Merged содержит служебные области и может перезаписать обычную NVS; полный erase не нужен. RainMaker factory-раздел не включён в компактный образ.

Проверки: реальная сборка ESP32-S3; формат/контрольные суммы/validation hash/разметка и границы двух BIN; 12 комбинаций ширины/темы Chromium для нового UI; прежние браузерные тесты калькулятора и Wi-Fi; выполнение production keypadAction с аппаратными заглушками; 144 комбинации геометрии нового TFT renderer; 24h/NaN/gaps/millis-rollover для production history; BLE/OTA/Wi-Fi/калькулятор и контракт сохранности аппаратного ядра/RainMaker.
Старый тест сохранности распознавал WIFI1 по дате в версии; привязка заменена на наличие BUSA_WifiScan.h, так как версия UI6 другая. Хеши исходных функций и модулей не ослаблены; специфичный контракт Wi-Fi/клавиатуры также выполнен.

На физическую ESP32 сборка не устанавливалась. Макеты в тестовых screenshots используют явные fixtures; они не являются показаниями устройства. Сборка и проверки на ПК не подтверждают оптическое качество реального TFT и аппаратную работоспособность.
