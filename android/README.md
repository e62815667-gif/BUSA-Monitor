# БУСА для Android 1.1.0

Пакет `ru.busa.monitor`, версия `1.1.0-UI16`. Те же шесть экранов UI16,
аппарат и калькуляторы, что в локальном интерфейсе ESP32.
Android 6.0+, актуальный Android System WebView.

## Доступ через мобильный интернет

Это основной режим. Телефон использует свой интернет, без подключения
к Wi-Fi прибора. Цепочка данных: ESP32 → Google Apps Script / таблица → Android.

При первом запуске указать ссылку Google Apps Script `/exec` и отдельный
ключ просмотра `BUSA_VIEW_TOKEN`. Ключ находится в свойствах существующего
Apps Script, где была выполнена `setupBusaSheet`. Не вводить ключ записи
ESP32 `BUSA_TOKEN` и не присылать ключи в чат. Ключ просмотра хранится только
в закрытых настройках Android; в HTML, JavaScript и APK он не встраивается.
Резервное копирование приложения отключено.

Нативный клиент получает JSONP как текст, проверяет JSON, устройство и
возраст записи. JavaScript из ответа Google не выполняется. HTTPS и проверка
сертификата обязательны; перенаправления разрешены только на два домена
Google Apps Script. В релизе произвольные серверы и HTTP не разрешены.

Запрос выполняется в фоне каждые 30 секунд. В верхней строке видно время
последней записи или конкретную ошибку. Данные старше двух минут,
пустая таблица и отклонённый ключ не превращаются в текущие показания.
Отсутствующие датчики остаются «Н/Д». Статус ESP32 в этом режиме означает
свежую телеметрию прибора; время получения видно над интерфейсом.

Калькуляторы работают и без связи. Графики показывают только имеющиеся
измерения с пропусками в соответствующих временных интервалах. Старый
приёмник Google передаёт историю температур; отсутствующая история расхода
не заменяется вымышленной линией.

Облачный канал передаёт телеметрию. Изменение Wi-Fi прибора, калибровка,
пороги, обучение клавиатуры и загрузка прошивки требуют прямого Wi-Fi
подключения; соответствующие кнопки в режиме просмотра отключены.
Приложение не подтверждает сохранение неподдерживаемых удалённых команд.
Фоновая сигнализация при закрытом приложении в эту версию не входит.

## Прямое подключение

Кнопка «Назад» на главной или строка подключения открывает меню:
повторить, доступ через интернет, подключение по Wi-Fi, адрес и выход.
Для прямого доступа выбрать Wi-Fi БУСА и адрес (обычно `192.168.4.1`).
Приложение использует сеть Wi-Fi даже без интернета. В облачном режиме
привязка к Wi-Fi снимается и используется интернет телефона.

Прямая страница загружается с ESP32 без короткой предварительной проверки
API. Ожидание первой страницы — до 30 секунд. При ошибке видны адрес и
причина. После возврата из настроек или появления сети приложение повторяет
соединение, если было без связи. Рабочую страницу при возврате из выбора
BIN не перезагружает. Для WebView до Chromium 103 есть совместимость
`AbortSignal.timeout`, необходимая опросу и поиску сетей на ESP32.

Список сетей запрашивается у самого ESP32. Приложение не запрашивает
геолокацию и доступ к списку сетей Android. Все локальные проверки и
ограничения настройки ESP32 сохранены.

## Сборка и подпись

Сборка выполняется в GitHub Actions, ветка `feat/busa-android-ui16`.
`busa-android.yml` компилирует APK, запускает эмулятор Android 15 и выдаёт
артефакты APK, снимки и отчёты. Ключи доступа пользователя и ключ подписи
в исходники и артефакты не добавляются.

Для передачи пользователю предназначен release APK с `debuggable=false`.
Actions также строит подписанный временным ключом debug APK только для
проверок WebView. Его не следует выдавать как окончательное приложение.
Actions создаёт unsigned release APK для окончательной подписи постоянным
ключом в закрытом рабочем каталоге. Подпись меняет только подписи ZIP,
а не DEX, ресурсы и HTML; это проверяется при выдаче.

Если установлена прежняя тестовая версия с другим ключом, Android потребует
удалить её перед установкой релиза. Локальные данные тестового приложения
при удалении теряются. Последующие релизы подписываются тем же постоянным
ключом. Отпечаток постоянного сертификата SHA-256:
`180c6831a261b8f19d1f6c13710a811ab5859986438e84ed2afd7720c71887b3`.

Начиная с MOTION1 используется новая постоянная подпись. Для перехода с другой
подписи требуется переустановка; сохранённые настройки приложения на телефоне
при удалении сбрасываются.

Зависимости: Java 21, Python 3.10+, SDK Platform 35, Build Tools 35.0.0.
Gradle и внешние библиотеки приложения не требуются.

```sh
python3 ci/generate_android_assets.py --check
python3 android/tests/test_source.py
python3 android/build.py --sdk /path/to/sdk --unsigned --out android/out/release
```

## Проверка

Исходные проверки контролируют точные байты UI/калькуляторов, адреса,
разрешения, запрет небезопасных серверов/редиректов и отсутствие JS-моста.
Сценарий прямого доступа охватывает запуск без ESP32, восстановление,
задержку страницы на 6 секунд, отсутствие `AbortSignal.timeout`, список
сетей, шесть разделов, калькулятор, выбор BIN, Back и потерю связи.

Отдельный сценарий облака отключает Wi-Fi эмулятора и проверяет получение
данных через мобильный интерфейс, шесть экранов, калькулятор, недоступный
ключ, пустую таблицу, устаревшую запись, восстановление и отсутствие ключа
в WebView. Google и ESP32 в автоматических проверках представлены HTTP
fixtures. Подключение к реальному Google пользователя и физическому прибору
нужно проверять отдельно; успешный эмулятор не подтверждает их доступность.

У пользователя зафиксировано: ESP32 подключён к роутеру, но Google
показывает HTTP −1 / TLS −1 — сетевое соединение не установлено.
Пока загрузка ESP32 → Google не заработает, удалённый Android не сможет
получить свежие показания. Сам по себе новый APK этот сетевой сбой не устраняет.
