# БУСА для Android 1.0.0

Приложение с тем же интерфейсом, который доступен в браузере ESP32.
Пакет `ru.busa.monitor`, версия `1.0.0-UI16`. Android 6.0 и новее,
с обновлённым Android System WebView (Chromium 103+).

## Использование

1. Установить `BUSA_Android_1.0.0_UI16.apk` на Android. При необходимости
   разрешить установку для приложения, из которого открыт APK.
2. Подключить телефон к сети Wi-Fi БУСА. Интернет не требуется.
3. Открыть приложение «БУСА». По умолчанию адрес прибора `192.168.4.1`.

Кнопка «Назад» возвращает из раздела на главную, из подраздела настроек —
в список настроек. На главной она открывает меню подключения: повторить,
настройки Wi-Fi телефона, адрес прибора и выход. На шести рабочих экранах
дополнительной панели приложения нет.

При наличии связи загружается настоящий HTML с ESP32: новые изменения
прошивки становятся доступны при следующем подключении. Дизайн и
поведение не копируются в отдельные нативные экраны.

Если прибор недоступен, открывается встроенная копия UI16, извлечённая из
тех же исходников. Калькуляторы доступны без прибора. Значения датчиков
остаются «Н/Д», а не заменяются демонстрационными числами. Опрос идёт
на настоящий адрес; при восстановлении сети данные снова поступают.
Чтобы загрузить новую версию страницы с прибора, выбрать «Повторить
подключение» в меню. Данные калькуляторов хранятся на телефоне по адресу
прибора, как в локальном браузере.

Для обновления ESP32: Настройки → Обновление ПО → выбрать APP_OTA.bin.
Android открывает системный выбор документов; доступа ко всему хранилищу
или отдельного разрешения на файлы не требуется. USB_MERGED для OTA
использовать нельзя. Приложение не меняет проверки и порядок OTA в прошивке.

Оболочка использует подключённую Wi-Fi сеть даже без интернета, не сканирует
имена сетей и не запрашивает геолокацию. Единственные разрешения — интернет,
состояние сети и привязка процесса к сети. Нет рекламы, аналитики, платного
сервера, JavaScript-моста к Android или облачного доступа. Ссылки из рабочего
интерфейса на внешние HTTPS-страницы открываются в браузере телефона.

Фоновая сигнализация при закрытом приложении в эту версию не входит.
Датчики, реле и автономная сигнализация самого ESP32 работают по прошивке.

## Сборка и подпись

Зависимости: Java 21 (включая модуль `jdk.compiler`), Python 3.10+,
официальный Android SDK Platform 35 и Build Tools 35.0.0.
Gradle и внешние библиотеки приложения не требуются.

```sh
python3 ci/generate_android_assets.py
python3 android/tests/test_source.py
export BUSA_KEYSTORE_PASS='пароль своего хранилища'
python3 android/build.py --sdk /path/to/android-sdk \
  --keystore /private/busa-release.jks --out android/out
```

Ключ с псевдонимом `busa` должен быть создан один раз и храниться отдельно
от репозитория. Для обновления уже установленного приложения требуется
тот же ключ. Скрипт не печатает пароль, не включает ключ в APK и не
загружает его в сеть. `--debug` включает отладку WebView только для тестов;
итоговый APK собран без этого флага. Сборщик проверяет min/target SDK,
пакет, отключённую отладку, подписи v1/v2/v3 и точное содержимое UI.

Сертификат первой сборки, SHA-256:
`3e63affe2693ecb7c62cb96c2aa5d17c507f28ef1db3eeb030fe1674ee3e815b`.
Это публичный отпечаток сертификата, не ключ.

## Проверки и ограничения

Проверены компиляция Java/DEX/ресурсов, подпись APK, точное совпадение
HTML/JS/CSS с прошивкой, адреса и границы навигации, состав разрешений.
Браузерная проверка встроенной копии охватывает отсутствие ложных показаний,
калькулятор без ESP32, восстановление опроса и отсутствие команд при переходах.
Проверки UI16 для шести разделов на восьми размерах окна остаются в проекте.

Запуск эмулятора API35 в этой среде ограничен свободным местом и отсутствием
KVM. Проверка на реальном Android с физическим ESP32 ещё нужна, в том числе
привязка к Wi-Fi без интернета и передача выбранного BIN в ESP32. Успешная
сборка APK не объявляется такой проверкой.
