# БУСА 14.14v — исправление ложного цикла OneWire

**Плата:** ESP32-S3 N8R2, 8MB Flash. **Режим:** только мониторинг, выходы K1–K4 отключены.

## Причина выпуска

В БУСА 14.13v при отсутствии всех четырёх DS18B20 функция `sampleTemperatures` всё равно выставляла `tempConverting=true`, словно датчики начали измерять температуру. Это приводило к фиктивному ожиданию без настоящего измерения. Независимая диагностика OneWire в таком состоянии могла пропускать опрос во время ожидания.

## Исправление

В функции `sampleTemperatures` новый цикл считается активным **только если хотя бы один** датчик присутствует. Если датчиков нет, немедленно разрешается диагностика OneWire: `tempConverting=false`, `tempRequestAt=0`.

Это изменение устраняет **ошибку программного состояния**, но не гарантирует, что ранее отсутствующие датчики станут обнаруживаться. Сообщение `NO_PRESENCE` требует фактического ответа OneWire и может остаться, если его нет. Результат определит реальная телеметрия после обновления; повторные аппаратные проверки без новых оснований не назначаются.

## Сохранено

- Wi-Fi AP, локальный iPhone web UI и ручной APP OTA.
- Отправка телеметрии в Google с текущими настройками.
- TFT и I2C PCF8575/PCA9685.
- GPIO38–GPIO41 для температур, прочие утверждённые GPIO без изменений.
- Исполнительные выходы K1–K4 и PWM физически не используются.

## Файлы выпуска

- `БУСА 14.14v APP OTA.bin` — **только для ручного обновления через локальный Wi-Fi**.
- `БУСА 14.14v USB MERGED.bin` — только резервный образ для сервисного восстановления.
- `БУСА 14.14v SHA256.txt` — контрольные суммы.

**До успешной CI-сборки и проверки контрольных сумм файлы не считать готовыми.** После загрузки APP OTA проверить идентификатор `БУСА 1М WiFi 14v14-N8R2-ONEWIRE-FIX`, передачу Google и новые результаты `wireProbe` по T1–T4. Старую V14.13v сохранить для отката. Установку выполняет только владелец, автономного/облачного перепрошивания нет.
