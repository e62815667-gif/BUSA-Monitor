## Functional chain
1. ESP32-S3 connects to the user-owned Google Apps Script endpoint with an already configured token; continues existing 30-second diagnostic HTTPS POST (with verified TLS certificates).
2. Revised `google/BUSA_GoogleSheets_Receiver.gs` can add a validated, public, **read-only** `release` object to the `{"stored":true,...}` ACK. No binary or remote command is transmitted.
3. `BUSA_Google.h` parses strict version/target/SHA-256-format/byte size/flash size metadata with memory bounds; publishes results as `google.cloud_update` in `/api/status`.
4. Embedded local iPhone web app shows Google release version, ESP Flash size, release build size and an explicit **remote install locked** status. It retains the standard local/manual APP OTA function.
5. The public cloud dashboard displays the catalogue from `online/releases.json` and the controller's preflight diagnostics once firmware is installed and the Google Apps Script is deployed.

## User-owned Google Apps Script deployment required
- Open the **existing** Google Sheet's Apps Script project (currently receiving BUSA_telemetry).
- Replace the existing script with the revised source at https://github.com/e62815667-gif/BUSA-Monitor/blob/lab/busa-v14-12-cloud-update-preflight/google/BUSA_GoogleSheets_Receiver.gs .
- Do **not** reset Script Properties or change `BUSA_TOKEN`, `BUSA_VIEW_TOKEN` and `BUSA_SPREADSHEET_ID` during replacement.
- Run once `setupBusaReadOnlyReleaseV1411` as owner. It configures only version/target/size/SHA metadata for the **existing V14.11** release.
- Deploy a **new version** of the existing Apps Script Web App. Keep its prior execution identity and access rules; ensure the URL stays the same if possible. Do not publish tokens.
- Only after a tested, compatible firmware is installed: verify that Google confirms `stored:true`, and `/api/status` reports `google.cloud_update.catalog_seen=true`. The value `remote_install_enabled` must remain **false**.

## Unresolved blocking tasks for REAL remote install
1. **Hardware mismatch:** earlier field notes suggest ESP32-S3 N16R8 / 16 MB Flash / 8 MB PSRAM; this build uses ESP32-S3 with **8 MB Flash, PSRAM disabled** and `default_8MB` partitions. Establish chip module, flash/PSRAM, installed partition scheme, OTA slot and recovery before installing anything.
2. To safely apply firmware over internet, define a trust-anchored release signature (cryptographic signature of manifest and image, not SHA alone), compatibility policy, verified TLS distribution, safe download, atomic swap and confirmed rollback. Do not rely on read-only JSON over an untrusted publisher as an authorization signal.
3. Require a local operator to confirm that the separate equipment is in a safe idle state and external physical actuator outputs remain disconnected. **No unattended cloud Flash rewrite.**
4. Field validation under power and Wi-Fi interruption with a verified backup and USB recovery plan.

**PASS in GitHub Actions is compile/static test only, not real-device or remote OTA verification.**
