APP OTA не заменяет таблицу разделов. **Не передавайте USB MERGED в локальный OTA.**

## Точный целевой профиль

ESP32-S3 **N16R8**, Arduino ESP32 **2.0.17**, Flash 16 MB,
меню **QIO 80 MHz**, **OPI PSRAM**, USB CDC on boot / hwcdc, DebugLevel=none.
Используется исходная `partitions.csv`: app0 от 0x10000 и app1 от 0x310000,
размер каждого **0x300000**. N8R2 и разметка SAFE1 из прежней работы не подходят
как автоматически взаимозаменяемые варианты.

В Arduino 2.0.17 меню QIO задаёт DIO-заголовок ROM-стадии с QIO boot-кодом.
Поэтому `image_info` закономерно показывает Flash mode DIO; упаковщик сохраняет
эти байты. Это не самовольная смена выбранного профиля на другой.

Локально: Arduino CLI 1.3.1, Xtensa GCC 8.4.0 esp-2021r2-patch5,
esptool 4.5.1, 4 задания. Программа 2010273 байта (63% от 3145728),
статическая RAM 77532 байта (23%); по отчёту компоновщика остаётся 250148 байт.
Это не измерение heap/PSRAM на контроллере.

Библиотеки закреплены: OneWire 2.3.8, DallasTemperature 4.0.6,
BusIO 1.17.4, GFX 1.13.0, ST7735/ST7789 1.12.0, ILI9341 1.7.0,
U8g2_for_Adafruit_GFX 1.8.0; ESP RainMaker/WiFiProv поставляются с core 2.0.17.
Использован чистый официальный core, не модифицированный framework прежних заданий.
SDK включает CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y; механизм не отключался.

## Что проверено

- Реальные C++ функции callback/provision, lifecycle BLE, OTA boot confirmation,
  перенос credentials выполнены с SDK/NVS-моделями: четыре проверочные программы.
- Успех credentials не даёт restart до END; stop запрашивается один раз;
  проверены init/advertising/общий/cleanup timeout и переполнение millis.
- Проверены pending/valid/error OTA и отсутствие API принудительного выбора
  boot partition; интеграционные guards не дают BLE-restart pending-образа.
- Проверены NVS sync, readback, отказ записи и rollback прежней пары, SSID 32 байта,
  неподдерживаемые длины пароля и сохранение staOff.
- Три бывших patch-скрипта дважды запущены без изменения байтов исходников.
- Четыре unittest контракта телеметрии прошли; JavaScript двух страниц проверен Node.
- 10 соседних файлов и 14 существующих реализаций функций совпали с фактической
  FIX2 после старой цепочки преобразований. Хэши записаны в PRESERVATION_CHECKS.json
  общего архива. Неизменённая прошивка просто с новым номером не выдаётся за ремонт:
  конкретные изменённые участки видны в diff коммита.
- Проверены chip ID 9, APP descriptor, внутренние checksum и validation hash,
  версия FIX3 внутри APP, размеры OTA-слотов и таблица разделов.
- Bootloader/partitions/boot_app0 в USB совпадают с входами; APP целиком совпадает
  с хвостом USB от 0x10000. Оба SHA-256 повторно проверены.
- Source ZIP совпал с исходниками фактической компиляции, включая generated CA.

Первый локальный compile выявил отсутствующий явный include esp_wifi.h для нового
чтения конфигурации STA. Include добавлен; повторная компиляция и CI успешны.
Предупреждения локального CLI о неустановленных serial/mdns/dfu discovery относятся
к загрузке/обнаружению устройств; при выполненной компиляции они не использовались.
Проверки TLS, доверенных CA и контрольных сумм загрузок не отключались.

## Что проверить на настоящем устройстве

1. В ESP RainMaker для iPhone искать `PROV_BUSA_…` со стандартным фильтром `PROV_`.
   Код сопряжения сохранён прежним, брать его из локального приложения.
2. После CRED_SUCCESS дождаться штатного окончания и обычного запуска БУСА;
   проверить локальный AP, выбранную сеть, устройство в аккаунте владельца,
   сохранённые настройки и настоящую доставку Google.
3. Если STA явно выключен локальным пользователем, это решение сохраняется:
   для cloud требуется отдельно разрешить/подключить STA в локальной панели.
4. Проверить OTA с установленной совпадающей разметкой и реальное поведение после
   restart. Валидный новый образ подтверждается после готовности NVS/AP/HTTP;
   ошибочный старт, проблемы Flash/питания и watchdog по-прежнему могут законно
   приводить к recovery/rollback. Без проверки bootloader и логов конкретной
   платы нельзя обещать устранение любого наблюдавшегося «отката».

Эти пункты **не выполнены физически** в облаке. Модели не подтверждают BLE-радио,
реальный iPhone, электрическую совместимость, исправность Flash/PSRAM, облачный
аккаунт, корректность wiring или отсутствие аппаратных перезагрузок.
