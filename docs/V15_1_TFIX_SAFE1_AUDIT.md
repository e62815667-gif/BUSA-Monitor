# БУСА-1М №001 — аудит V15.1 TFIX SAFE1

База: `handoff/codex-source-v15-1-tfix-20261027`,
`ae636ca2094f7bf219453e9cae8fba9b8f903157` (handoff исходников 62b6289d).
Изменения: новая ветка `fix/v15-1-tfix-safe-startup-20261027`.
Версия: `15v1-N8R2-FOUR-SOUND-ALARMS-TFIX-SAFE1`.
Название унаследовано для совместимости; физическая сигнализация **заблокирована**.

## Доказанные по коду проблемы и исправления

1. **K1–K4:** Board.h содержал комментарий «не OUTPUT», но разрешал физические
   выходы; Alarm.h реально задавал OUTPUT с предполагаемым active LOW. SAFE1
   удаляет физический драйвер целиком, оставляет GPIO7/6/5/4 INPUT/no pull,
   блокирует старые разрешения NVS и все четыре HTTP-запроса включения (423).
   Гистерезис и четыре независимых поля остаются логикой без аппаратной активации.
   JSON больше не сообщает о включённом драйвере: relays_enabled=false,
   driver_enabled=false, trigger_level=null, reason=HARDWARE_LOCKED.
2. **Неоднозначные DS18B20:** ручная привязка позволяла считать достоверным ROM,
   одновременно замеченный на разных GPIO. Такой обход убран. Даже явная привязка
   не преодолевает LINE_LOW, плохой CRC, одинаковый ROM на нескольких DATA или
   назначение одного физического ROM двум логическим ролям.
3. **Электрические и адресные ошибки:** LOW до/после reset имеет отдельный статус,
   даже если прежний инвентарь ещё содержал датчик. Разделены CRC адреса,
   неподдерживаемое семейство, шум поиска, отсутствие presence/ROM, несколько ROM,
   пропавший назначенный ROM и устаревшее измерение. Никаких «запасных» температур.
4. **Свежесть:** добавлена проверка завершения конверсии busy-bit после 825 мс;
   незавершённая конверсия даёт CONVERSION_TIMEOUT, а не новый timestamp старому
   scratchpad. Значения/время/валидность логических каналов синхронизируются после
   каждого шага. Убрано окно до 500 мс, когда hasTemp уже true, а temperature[]
   ещё NAN: оно могло породить недопустимое числовое значение в JSON.
5. **Намеренно не назначенный датчик:** выбор «Не назначен» / `none` сохраняется
   как версия 2 записи привязок. Старые корректные записи версии 1 читаются.
   Повреждённая существующая запись больше не возвращает молча режим auto:
   все роли становятся UNASSIGNED, temperature_binding_record_error=true.
   Отсутствие записи при первом запуске сохраняет документированное auto по GPIO.
6. **PCF8575:** ошибка повторного чтения при проверке конфликтующих линий ранее
   игнорировалась и могла выглядеть как ошибка матрицы. Теперь это SCAN_READ_FAILED,
   без события клавиши, с попыткой отпустить порты. Добавлены текстовые reason-коды.
   `error=6, mask=c0` воспроизводится моделью связей P6/P7 при drive=P0; это
   неоднозначное чтение, а не доказательство конкретного порядка проводов или
   неисправного чипа. Раскладка 5×4 по-прежнему обучается по настоящим контактам.
7. **Интерфейсы:** ВКЛ, °C / ОТКЛ, °C независимы для T1–T4, без добавления слов
   «Звук»/«Сигнализация» к меткам полей. На TFT — LOW / NO DS / ROM? / STALE /
   UNSET вместо одинакового Н/Д для всех причин. Добавлен read-only `/expert`,
   доступный только из локального AP и без кеша, с полной диагностикой JSON.

Wi-Fi AP+STA, обработка повторного соединения, HTTP и Google, GPIO датчиков,
TFT, клавиатуры и расходомера не переназначались. Параметры рабочей сети не
менялись. Пароли/токены не добавлялись в отчёт. TLS остаётся обязательным,
облачная установка отсутствует. V13/V14-заголовки, стабильные снимки и сама
handoff-ветка не редактировались: активный TFT-рендерер SAFE1 — отдельный новый файл.

## Проверки

Выполняются реальные функции поставляемых заголовков с моделями устройств:
`test_temperature.py`, `test_gpio_safety.py`, `test_keypad.py`,
`test_wifi_recovery.py`, `test_v15_sound_alarms.py`; а также все имеющиеся
Python/Node-тесты интеграции, интерфейса, Google и архитектуры.
GPIO-тест компилирует драйвер без определений OUTPUT/HIGH/LOW/digitalWrite,
проверяет игнорирование старых NVS-флагов, блокировку HTTP и сбои записи.
Температурные тесты включают именно GPIO17/18 LINE_LOW при исправных T1/T4,
CRC, уникальность, none, повреждённый NVS, timeout конверсии, свежесть и millis wrap.
PCF-тесты проверяют контакты, mask=c0, все I/O-ошибки, отпускание и произвольный
обученный порядок строк/столбцов 5×4.

Это программные тесты, **не проверка электрической схемы или физических модулей**.
Действительную причину повреждения прежнего контроллера они не устанавливают.
Результаты сборки, SHA-256 и ссылка GitHub Actions публикуются отдельно в
`releases/V15_1_TFIX_SAFE1_RESULTS.md` после завершения выпуска.

## Что проверить отдельно на новом оборудовании

Сначала выполнить [проверку соединений](V15_1_TFIX_SAFE1_WIRING.md), не подключая
нагрузки. Требуются настоящие измерения GPIO17/18, питания/подтяжек DS18B20,
PCF8575, интерфейсов 3,3 В, VCC/JD-VCC, OE PCA9685 и моделей TFT/реле.
Состояние каждого старого датчика неизвестно. После отдельного разрешения на
стенд проверить T1–T4, матрицу, Safari, AP+STA, реальные записи Google и отсутствие
импульсов на K1–K4 при подаче питания/RESET/OTA. Здесь эти действия не выполнялись.
Возврат старой прошивки может снова применить прежние NVS-флаги выходов;
без аппаратной проверки такой возврат не является безопасным обходным решением.
