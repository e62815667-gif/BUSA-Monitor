# БУСА-1М №001 — CALC2: калькулятор в ESP RainMaker

Версия `14v9-N16R8-RM-CALC2-20261105`, продолжение CALC1 на BLE FIX3.
Рабочая ветка feat/busa-calculator-20261105; main и готовые CALC1/TELEM2 не меняются.

Владелец уточнил: «онлайн-приложение» — **ESP RainMaker**, не GitHub Pages.
Поэтому публикация веб-страницы больше не является условием задачи, её workflow
оставлен только с ручным запуском. Разрешать ветку в github-pages не требуется.

## Как найти калькулятор

После OTA и синхронизации конфигурации узла в существующем ESP RainMaker должны
появиться **три стандартные карточки**:

* «Калькулятор · Разбавление»: объём спирта/начальная/нужная крепость,
  «Рассчитать», «Сбросить», статус, долить воды, объём смеси.
* «Калькулятор · Ареометр»: температура/показание, те же команды,
  статус и крепость при 20 °C.
* «Калькулятор · Перегонка»: объём/крепость сырца, крепость продукта,
  доли голов/хвостов от АС, команды, статус, АС/головы/хвосты/выход.

Это native устройства **esp.device.other** и параметры **esp.ui.text/toggle**
официального SDK Espressif. Прошивка не устанавливает сторонний iOS-клиент и не
добавляет собственные вкладки/жёлтый веб-дизайн внутрь приложения RainMaker.

Введите параметры через Edit, затем включите переключатель **«Рассчитать»**.
ESP32 обрабатывает его в основном цикле и возвращает результат со статусом
«Готово». Переключатель сбрасывается в Off при следующем общем отчёте, целевой
интервал до ~10 секунд при исправной сети (не гарантия задержки Интернета).
«Сбросить» очищает только поля соответствующего калькулятора.

До расчёта и после изменения/ошибки входа результат — **«—»**, не нулевое или
устаревшее вычисление. Результаты readonly, числовые входы read/write.
Вывод — строки с двумя десятичными знаками и запятой, единицы указаны.

После обновления обновите список устройств/перезапустите приложение RainMaker
для загрузки новой конфигурации. **Не удалять зарегистрированную БУСА и не
выполнять повторное BLE-сопряжение.** Сохранение identity/NVS предусмотрено
разметкой и неизменённой политикой OTA, на реальном новом OTA ещё не проверено.

## Архитектура и сохранность

Добавлены BUSA_RmCalcState.h и BUSA_RainMakerCalc.h. Из callback в RAM-очередь
ставятся только типизированные ограниченные команды. Callback не вычисляет,
не публикует и не пишет NVS/GPIO. Основной цикл проверяет диапазоны и вычисляет
через тот же BUSA_Calculator.h, что TFT. Облачные, TFT и браузерные поля
независимы; никакого автоматического изменения показаний/порогов/выходов.

Снимок телеметрии содержит неизменяемую копию результатов. Worker обновляет
только изменившиеся calculator revisions и отправляет **один общий пакет**
вместе с T1–T4 и uptime. Отдельных MQTT-публикаций на каждый ввод нет.
Ошибка модели одного калькулятора не останавливает основные температуры.
При транспортном отказе значения повторно ставятся в следующий пакет.
SDK копирует строковые значения параметров; после release снимка буферы
прошивки не используются в качестве постоянного хранилища SDK-параметров.

Существующие имена/типы T1–T4/Google/здоровья/экрана/клавиатуры сохранены;
новые устройства добавляются в node до RMaker.start, официальный BLE не менялся.
Публикация T1–T4 с округлением до десятых и интервалом 10 секунд сохранена.
NVS/fctry, Google-транспорт, AP+STA, GPIO, звук, датчики и OTA не переписывались.
В `/api/rainmaker/status` → telemetry добавлено `calculator_devices_ready`:
ожидается 3. Это число локально созданных моделей, **не подтверждение доставки
конфигурации или отображения карточек в реальном облачном приложении**.

## Расчёты и ограничения

Условия, единицы АС, клавиатура TFT, лицензия MIT/OIML и локальный веб-интерфейс
описаны в [RM_CALC1_BUILD.md](docs/RM_CALC1_BUILD.md) (путь внутри ZIP).
* Разбавление — массовый баланс при 20 °C с контракцией.
* Ареометр — 0…40 °C, стеклянный спиртомер на 20 °C, чистый водно-спиртовой
  раствор без сахара, номинальное расширение стекла 25e-6/°C. Оценка, не поверка.
* Вторая перегонка — доли от АС; головы/хвосты в **литрах АС**, не реальные
  объёмы фракций; дополнительная потеря спирта не моделируется.

## Сборка и установка

CLI 1.3.1, ESP32 Arduino 2.0.17, прежние библиотеки/CA и N16R8-разметка CALC1.
Готовый APP ≤ 3MiB. .github/workflows/busa-calculator.yml содержит полный процесс.

```
python3 ci/generate_calculator.py
python3 ci/generate_google_ca.py --output firmware/BUSA_1M_WIFI_3v_GOOGLE/BUSA_GoogleCA.h
arduino-cli compile --clean --fqbn 'esp32:esp32:esp32s3:FlashSize=16M,PartitionScheme=app3M_fat9M_16MB,PSRAM=opi,CDCOnBoot=cdc,USBMode=hwcdc,FlashMode=qio,DebugLevel=none' --output-dir out firmware/BUSA_1M_WIFI_3v_GOOGLE
python3 ci/package_rainmaker_calculator.py --build-dir out --core-dir /path/to/esp32/2.0.17 --esptool /path/to/esptool_py/4.5.1/esptool.py
```

Для зарегистрированной БУСА использовать **OTA BIN** в локальном 192.168.4.1.
OTA сохраняет NVS/fctry по конструкции. USB MERGED — с 0x0, затрагивает обычный
NVS/настройки и требует резервной копии; не выбирать USB в OTA, не erase-all.
Проверки chip ID/image checksum/hash/APP boundaries/USB layout выполняет упаковщик.

Физический ESP32 не прошивался. На оборудовании остаются обязательными:
реальное появление трёх карточек, ввод и обратная доставка результатов,
одновременное обновление T1–T4/uptime, reconnect/RESET/OTA без регистрации,
TFT/PCF8575 и длительная работа TLS/памяти/SDK worker stack.
Окончательный CI/размеры/SHA/ссылки записаны в отчёте выпуска.
