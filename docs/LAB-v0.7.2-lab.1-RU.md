# БУСА-1М №001: v0.7.2-lab.1
16.10.2026. Реальное чтение температур и локальный мониторинг; НЕ рабочая автоматика.

## Реализовано
- ESP-IDF 5.3.2 + Arduino Core 3.1.3; сборка без Arduino IDE.
- Четыре DS18B20, каждый на отдельном CH0–CH3 DS2482-800. GPIO8=SDA, GPIO7=SCL.
- Проверки ROM/CRC, внешнего питания датчика, начала и завершения преобразования; ошибки и возраст измерения. Никаких подставных измерений.
- Wi-Fi AP+STA, локальная HTML-страница, GET capabilities/telemetry/keys, GET/POST settings.
- Раздельные nullable пороги предупреждения и автоматики, сохранение в NVS. Пока только сравнение T >= порог, НЕ K1–K4. Направления иной автоматики, задержки, гистерезис и аварийная защита не реализованы.
- Ручной объём 0–100 л, по умолчанию неизвестен. Датчик уровня не определён; level_mm=null. Не используется прежняя неподтверждённая формула литры×8.
- История до 1000 реальных ответов в браузере, экспорт JSON, отключение недостоверных/устаревших показаний, явный демо-режим без записи в реальную историю.
- Исходная структура вкладок приложения сохранена, калькулятор отложен.
- Датчики включаются только USB-командой для текущей загрузки после проверки схемы. При перезапуске снова отключены.

## Что не реализовано и почему
Физические реле постоянно запрещены: нет GPIO/команд управления. k_states=false означает блокировку в ПО, НЕ измерение состояния контактов и НЕ гарантию отключения внешнего блока.
Полного утверждённого BusaAutomation.h нет; его правила не выдуманы.
TFT отключён: GPIO, контроллер и питание не подтверждены.
Клавиатура отключена: нет карты матрицы; фотоаудит противоречиво называет PCF8575 и PCF8574.
PCA9685 не получает команд: предназначен для LED-индикации, а не релейных катушек; его соединения/токи не проверены.
Wi-Fi не означает доступ к устройству из интернета. Нет облака, проброса портов или удалённого управления.
Эта версия НЕ завершает проверку всех приобретённых модулей.

## Центральная панель
Только беспаечные макетные платы и провода. Адаптер 38P исключён по последнему решению владельца.
Предыдущая таблица маршрутизации через 38P в temporary-central-panel-2026-10-16.md больше НЕ является планом текущей сборки.
Распиновка шины GPIO8/7 подтверждена архивом, но это не подтверждение фактических проводов.
В фотоаудите упоминался INT у предполагаемого DS2482: у самой DS2482-800 нет вывода INT. Такое фото не доказывает модель модуля! Перед командой sensors прочитать маркировку микросхемы.
Исправление справочных адресов: DS2482-800 имеет три AD-пина, диапазон 0x18–0x1F (24–31), НЕ только 0x18–0x1B.
Без мультиметра и проверки питания/замыканий периферию не включать.
Реле и 12 В полностью отсоединены, любые исполнительные устройства/220 В вне стенда.

## Готовые файлы и сборка
Авторитетная сборка: workflow busa-v072-lab-build.yml. Артефакт имеет метку UNVERIFIED (на оборудовании).
В артефакте: merged BIN, SHA-256, BUILD_COMMIT.txt, flash_args, sdkconfig.
BIN объединяет bootloader 0x0, partitions 0x8000 и приложение 0x10000 из одной сборки.
Адрес записи одного merged BIN: **0x000000**. Параметры: ESP32-S3, DIO, 80 MHz, Flash16MB, Octal PSRAM8MB.
Не смешивать с «Итог 3.bin» или загрузчиками прошлых версий.
Рабочую v0.6.2-test на устройстве автоматически не заменять. Сначала сохранить имеющийся комплект и отдельно подтвердить переход на LAB.
Старая инертная main.cpp оставлена как исторический исходник; CMake компилирует **LabMain.cpp**, не обе точки входа.

### Ручная заливка после разрешения владельца
1. Снять всю периферию, оставить отдельную S3 и один проверенный USB-кабель.
2. В Windows убедиться в актуальном COM-порту; прежний COM4 не гарантируется.
3. Проверить SHA-256: PowerShell Get-FileHash .\BUSA-1M-001-v0.7.2-LAB-merged.bin -Algorithm SHA256.
4. В Espressif Flash Download Tool выбрать ESP32-S3, один merged BIN, адрес 0x000000; DIO/80MHz/16MB. Не запускать полное стирание для обычной записи.
5. После записи открыть UART через встроенный USB-UART порт, 115200, 8N1, без управления потоком; перезапустить плату. Оба USB одновременно не подключать.
6. Настройки этой версии лежат в NVS namespace busa-lab. NVS не шифруется: не передавать дампы памяти третьим лицам.
7. При ошибке NVS код не стирает раздел автоматически. Не применять erase_flash без отдельного решения и резервной копии.

## Настройка Wi-Fi без публикации пароля
Терминал отправляет одну JSON-строку с переводом строки LF:
{"cmd":"wifi","ssid":"ТОЧНОЕ ИМЯ СЕТИ","password":"ВВЕСТИ ЛОКАЛЬНО"}
Это шаблон, не команда с настоящими учётными данными. Ввести реальные значения только локально, не в GitHub.
Команда сохраняет сеть в NVS и начинает подключение. Пароль и SSID не выводятся обратно в журнал.
Через {"cmd":"status"} или периодический журнал прочитать IP. Подключение к точке iPhone12 требует проверки настроек 2.4GHz/совместимости телефона.
AP BUSA-1M-001 доступен для резервного локального подключения; случайный пароль выводится только в USB-журнал при загрузке и меняется после перезапуска.
Токен изменения порогов также случайный, только в USB-журнале, меняется при перезагрузке.
Не публиковать фото/логи с этими секретами.
Если USB-журнал не появляется, проверить USB-UART разъём/COM/скорость. Native USB CDC этой сборкой не настроен.

## Включение температурного узла — только после проверки
Три провода каждого DS18B20: 3.3V, DATA своего канала, GND. Не определять их по цветам.
После снятия питания подключить проверенный температурный узел; питание логики и подтяжки I2C 3.3 В.
После включения в USB-терминале, только если подтверждён адрес 0x18:
{"cmd":"sensors","address":24,"confirm":true}
Адрес десятичный 24..31 задаётся по фактическим AD2/AD1/AD0. Автопоиска/записи в неизвестные I2C-модули нет.
{"cmd":"sensors_off"} отключает опрос; НЕ отключает физическое питание модуля.
На канал ровно один DS18B20; паразитное питание не поддерживается.
Проверить сначала один, затем все четыре датчика: разумность температуры, ROM, CRC, обрыв, восстановление. 85°C допустимы только после проверенного преобразования.
Ни одного такого физического испытания при подготовке файла не выполнено.

## iPhone
Реальное приложение уже внутри BIN: Safari → http://IP-КОНТРОЛЛЕРА/ (IP из журнала).
Телефон должен иметь сетевой доступ к ESP32. Доступ именно с iPhone, раздающего точку доступа, проверить на устройстве; если недоступен, использовать второй телефон в той же сети либо AP ESP32.
В Safari можно добавить страницу на экран «Домой»; поведение запуска проверить на реальном iPhone.
Локальный HTTP не даёт полноценного service worker: при выключенной ESP32 повторное открытие локальной страницы офлайн не гарантируется.
HTTPS-вариант файлов index.html/lab-core.js/lab-app.js/sw.js/manifest.webmanifest имеет кэш оболочки и локальную историю, но не может читать HTTP ESP32 через смешанный контент.
Текущий публичный GitHub Pages в main не обновлён этой веткой. Ссылку существующего сайта нельзя выдавать за опубликованную новую версию.
Смена домена/IP создаёт отдельное браузерное хранилище; историю заранее экспортировать.
Токен настроек ввести из USB-журнала в разделе «Настройки». Он хранится только в поле страницы. После перезапуска ESP32 получить новый.
POST settings меняет только пороги/ручной объём, никогда сеть или реле. API без TLS предназначен исключительно для доверенной лабораторной сети; не открывать порт в интернет.
При HTTP409 загрузить настройки заново, затем повторить изменение. При потере связи сохранение блокируется.

## Контракт и проверки
GET /api/capabilities: сохранены старые поля; api_read_only относится к мониторингу/управлению выходами, settings_write=true отдельно разрешает настройки.
GET /api/telemetry: сохранены temperatures[4], channels[4], mode=MONITOR_ONLY, outputs_enabled=false, bridge_online, keypad_online, key_stream_id. Добавлены faults/ROM, volume_l, sensors_enabled, сравнения порогов.
GET /api/keys: пустой журнал, поскольку клавиатура не включена.
GET /api/settings: revision, warning[4], automation[4], volume_l, physical_outputs=false.
POST /api/settings: те же поля; Content-Type application/json и X-BUSA-Token; защита от устаревшей ревизии. Пустые значения null.
Существующий legacy /api/status не был реализован LAB-веткой; несовместимый старый формат не имитируется.
Проверки: python3 -m unittest discover -s tests -v; python3 -m unittest discover -s simulation/v0.7.2 -v; node --test tests/lab/*.test.cjs; g++ -std=c++17 -Itests/lab/stubs tests/lab/driver_test.cpp -o /tmp/busa-driver && /tmp/busa-driver.
Браузерный тест: tests/lab/browser_check.cjs, Playwright1.56.1 в отдельном CI, мобильный viewport Chromium. Это НЕ Safari и НЕ тест железа.
CRC/протокол тестируются моделью I2C, не реальным DS2482.
Сборка и программные проверки не подтверждают точность датчиков, электрическую безопасность, связь с iPhone или работу аппаратной защиты.
