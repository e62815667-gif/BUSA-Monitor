# БУСА-1М №001 — RainMaker Bluetooth / OTA FIX3

База: `fix/busa-ble-ota-stable-20261105`,
`2b7e8ceab88da06230efc77db4f1cfce14fb8cae`.
Исправления: `fix/busa-rainmaker-ble-rollback-audit-20261105`.
Версия: `14v9-N16R8-RM-BLE-FIX3-20261105`.

## Подтверждённые проблемы и изменения

1. **Скрытая смена исходников.** FIX2 CI последовательно запускал три генератора,
   изменявших Main/RainMaker и VERSION. Поэтому исходный checkout не соответствовал
   фактическому прошитому BIN. В FIX3 результат материализован в исходниках;
   entry point генераторов превращены в повторяемые read-only проверки. Новый
   workflow компилирует эти файлы без скрытой замены, что контролируется тестом.
2. **Обнаружение BLE.** Имя BUSA_… не соответствует стандартному фильтру PROV_
   в официальном RainMaker iOS. Используется PROV_BUSA_…; локальный SSID БУСА не
   переименован. Подсказка интерфейса соответствует реальному имени.
3. **Официальный протокол.** Сохранена схема Espressif Arduino 2.0.17:
   BLE + FREE_BTDM + SECURITY_1, PROV_INIT → disable_auto_stop(10000),
   CRED_SUCCESS → stop_provisioning. Ключ сопряжения не менялся и не выводится
   в новые служебные логи. Callback изменяет атомарные флаги, не String/NVS/GPIO.
4. **Преждевременный restart.** Раньше после CRED_SUCCESS начинался таймер
   перезапуска без ожидания PROV_END. Это могло оборвать выдачу результата телефону
   до завершения штатного grace period. Теперь успешный путь ждёт PROV_END и
   последующую паузу. В Arduino 2.0.17 WiFiGeneric сам вызывает deinit менеджера
   перед публикацией этого события; второе deinit не добавлялось. Остановка
   запрашивается один раз. Ошибка init, отсутствие advertising, общий тайм-аут и
   отсутствие END после остановки имеют ограниченные пути восстановления AP.
5. **Откат после OTA.** BLE-boot возвращался из setup до вызова подтверждения
   PENDING_VERIFY, затем сам делал restart. SDK собран с rollback: такой сценарий
   способен откатить ещё не подтверждённый образ. Теперь запрос сопряжения
   сохраняется, а новый OTA сначала проходит обычный локальный запуск; при готовых
   NVS/AP/HTTP подтверждается штатным esp_ota_mark_app_valid_cancel_rollback.
   Только затем допускается уже существующая перезагрузка в BLE-режим.
6. **Нельзя отменять выбранное OTA.** Убрана принудительная операция
   esp_ota_set_boot_partition(running) из проверки запуска. Она могла заменить
   выбор следующего образа текущим. Подтверждение теперь не меняет выбор раздела.
   Ошибка подтверждения не обходится и rollback bootloader не отключается.
7. **Разные хранилища Wi-Fi.** Телефон provisioned credentials в NVS ESP-IDF,
   а обычный запуск БУСА читал отдельные ssid/pass из Preferences. После успеха
   и END настройки явно переносятся в хранилище локальной панели главным потоком,
   с readback и восстановлением прежней пары при ошибке. Пароли не логируются.
   Явный `staOff` не меняется. Профили сети остаются в пределах существующих
   ограничений локального приложения; поддержка новых типов сетей не добавлялась.
8. **Обычный restart не является crash.** Остаточный rmCloudBusy раньше отключал
   RainMaker и после нормального software reset/питания. Recovery отключает cloud
   только при panic/watchdog/brownout в защитном окне; обычный запуск сохраняет
   разрешённый пользователем cloud. Ошибки реального init всё ещё обрабатываются.
9. **Упаковка USB.** Старый merge переписывал bootloader в QIO, хотя официальная
   board definition для меню QIO использует `build.flash_mode=dio` и QIO boot-код.
   Новый merge оставляет исходный заголовок (`keep`), проверяя байтовое совпадение
   всех входящих компонентов. Разметка и целевой профиль N16R8 не изменены.

## Что сохранено

Взята именно фактическая FIX2 после всех старых CI-преобразований. С ней побайтово
сравнены 10 соседних файлов, включая Google, клавиатуру/TFT, графику, звук и
partitions.csv, и 14 существующих реализаций функций: температуры, OneWire,
импульсы, I²C, PCF, общий Wi-Fi scan, локальная загрузка OTA, RainMaker callback
настроек и применение/публикация настроек. Они не менялись.

Все остальные отличия Main/RainMaker отражены в diff: запуск, lifecycle BLE,
подтверждение OTA, согласование NVS, служебные логи и подсказка имени BLE.
Распиновка, роли/пороги звука, утверждённые экраны, аппаратная логика, Google,
локальная навигация, AP+STA и локальный OTA не перепроектированы.
Облачный установщик OTA не включался: enableOTA был уже удалён фактическим FIX2 CI.

По-прежнему сопряжение — явный одноразовый BLE-boot. В это время локальный AP
временно недоступен; после завершения/тайм-аута выполняется обычный запуск AP+STA.
Одновременная непрерывная работа полного локального приложения в BLE-boot не
заявляется: это сохранённая архитектура исходной сборки, не новая функция.

## Основания Espressif

- [RMakerSwitch, Arduino ESP32 2.0.17](https://github.com/espressif/arduino-esp32/blob/2.0.17/libraries/RainMaker/examples/RMakerSwitch/RMakerSwitch.ino): порядок событий, Security 1, FREE_BTDM.
- [WiFiGeneric 2.0.17](https://github.com/espressif/arduino-esp32/blob/2.0.17/libraries/WiFi/src/WiFiGeneric.cpp): deinit при WIFI_PROV_END.
- [WiFiProv 2.0.17](https://github.com/espressif/arduino-esp32/blob/2.0.17/libraries/WiFiProv/src/WiFiProv.cpp): provisioning manager и стандартная BLE-схема.
- [Официальный RainMaker iOS, зафиксированный Configuration.plist](https://github.com/espressif/esp-rainmaker-ios/blob/418030af4ebbcfdd4311c2e87e8ac5546239408a/ESPRainMaker/ESPRainMaker/Configuration.plist): стандартный PROV_-фильтр.
- [ESP-IDF 4.4.7 OTA](https://docs.espressif.com/projects/esp-idf/en/v4.4.7/esp32s3/api-reference/system/ota.html): PENDING_VERIFY и подтверждение приложения.

Исходники core получены из официального release 2.0.17 с проверкой SHA-256.
Сведения о iOS сверены с неизменяемым коммитом; установленная на телефоне версия
приложения и пользовательские настройки фильтра не исследовались.

## Проверки и ограничения

`tests/test_ble_ota.py` компилирует настоящие C++ helper/callback/provision/credential
функции с SDK/NVS-моделями. Проверены событие INIT, ошибка→успех, stop-once, END,
тайм-ауты/переполнение millis, pending/valid/error OTA, отсутствие API reselection,
согласование credentials/ошибка записи/SSID 32 байта/границы пароля и отсутствие
скрытой записи исходников генераторами. Пройдены четыре unittest контракта
телеметрии и синтаксическая проверка JavaScript локального/внешнего приложений.
Результаты compile/CI и SHA-256 публикуются в отдельном файле выпуска.

Это модели и компиляция, не проверка BLE-радио, iPhone, действительных credentials,
облачной привязки владельца, Google Таблицы, питания/Flash/PSRAM и перезапуска платы.
Намеренный rollback при неисправном запуске, нарушении питания или ошибке Flash
не подавляется. Причинную связь с конкретным устройством без его логов/стенда
утверждать нельзя. Физический ESP32 не прошивался, не стирался и не перезапускался.
