# БУСА-1М №001 — переход на архитектуру V15.0 (ESP32-S3 N8R2)

## Состояние

Реализован отдельный от V14.27 исходный код с модульной компоновкой, сохранением маршрутов веб-приложения, DS18B20, Wi-Fi AP+STA, локального OTA и Google-диагностики. Версия `15v0-N8R2-MODULAR-MONITOR`.

Это **миграция архитектуры мониторинга**, а не заявка о готовности физических исполнительных устройств.

## Модули и ответственность

| Модуль | Ответственность |
|---|---|
| `BUSA_Main.h` | Подключение модулей, общие низкоуровневые компоненты и существующие обработчики |
| `BUSA_V15_Board.h` | Единственный контракт закрепления GPIO и статические проверки |
| `BUSA_Temperature.h` | Независимый опрос четырёх DS18B20, привязка ROM, ошибки |
| `BUSA_WifiRecovery.h` | Владение радио Wi-Fi AP+STA, фазовый поиск и повторное подключение |
| `BUSA_Google.h` | Отдельная Google HTTPS-задача и безопасная публикация данных |
| `BUSA_V15_RelayModel.h` | Изолированная логическая модель K1–K4, диагностическая имитация, без операций GPIO |
| `BUSA_V15_Status.h` | Телеметрия /api/status, совместимая с V14, и раздел architecture |
| `BUSA_V15_Architecture.h` | Версионированное описание модулей и ограничений |
| `BUSA_V15_Runtime.h` | Запуск, регистрация HTTP-маршрутов, кооперативный цикл задач |
| `BUSA_PCA9685_Leds.h` | Диагностика контроллера светодиодов без физической ШИМ-коммутации |

## Распределение ESP32-S3

- DS18B20: GPIO 16 / 17 / 18 / 21.
- PCF8575: I2C SDA GPIO 8, SCL GPIO 9, адрес 0x20.
- PCA9685: I2C адрес 0x40 (диагностика).
- Счётчик импульсов воды YF-S401: GPIO 15, входной уровень не выше 3,3 В.
- К1–К4: GPIO 7 / 6 / 5 / 4 — **логические назначения, физическая коммутация не реализована в этой прошивке**.
- ESP32-S3 N8R2: Flash 8 MB; PSRAM выключена; Arduino ESP32 core 2.0.17.

## Протокол и планировщик

- `setup()` вызывает регистрацию HTTP-маршрутов и создаёт инфраструктуру Wi-Fi / I2C / TFT / Google.
- `loop()` последовательно обслуживает независимые очереди: модель К1–К4, сеть, HTTP, Google, 1-Wire, счётчик воды, клавиатуру, TFT.
- Веб-клиент работает по локальному AP и опрашивает `/api/status` каждые 3 секунды.
- В ответе `/api/status` предусмотрено поле `architecture` с явным статусом модуля физических выходов.
- Процесс OTA временно останавливает обычные периферийные операции.
- Сохраняется локальная настройка Wi-Fi и удалённая **только диагностическая** передача Google.

## Что не входит в переход

Из ранее утверждённой области исключены силовой блок 220 В и моторизованный кран. Физическая коммутация реле К1–К4 в V15.0 не включена. Из имитации автоматически не делаются выводы о состоянии контактов или исправности питания 12 В.

Чтобы отдельно принять физическую часть, потребуются документированный безопасный алгоритм, характеристики драйвера, обработка пропадания питания/связи, а также независимая проверка на низковольтном испытательном стенде. **Нельзя считать такую часть выполненной по успешной компиляции.**

## Проверка

CI должен пройти `tests/test_v15_architecture.py`, прежние тесты Wi-Fi/Google/датчиков, компиляцию `arduino-cli`, создание BIN для USB/OTA и SHA-256. Аппаратные испытания ESP32 не выполняются в CI.

Базовая ветка V14.27 остается неизменной.
