# БУСА-1М №001 — CALC1

Версия: `14v9-N16R8-RM-CALC1-20261105`. База — проверенная TELEM2,
`ee6e659eacc2fd917b7c5f11b3a756c4b67606fa`, потомок BLE FIX3.
Отдельная ветка `feat/busa-calculator-20261105`; main и прежние выпуски сохранены.
Никакая физическая ESP32 не прошивалась.

## Что добавлено

Раздел **Калькулятор** в локальном приложении 192.168.4.1, онлайн-странице
(index.html) и физическом TFT (альбомная и портретная ориентация).
Три ручных расчёта выполняются без Интернета и без команд оборудованию:

1. Разбавление: объём, исходная и требуемая крепость → долить воды, конечный
   объём при 20 °C. Массовый баланс с плотностями OIML учитывает контракцию.
   Например, 1 л 96 % → 40 %: 1,47053 л воды, 2,40000 л готовой смеси.
2. Ареометр: температура 0…40 °C и показание 0…100 % → крепость при 20 °C.
   Для водно-спиртового раствора без сахара. Модель обычного стеклянного
   спиртомера с калибровкой 20 °C и номинальным объёмным расширением стекла
   25×10⁻⁶/°C. Конкретные приборы требуют своих поправок: это оценка, не поверка.
   Результат за физическими границами модели отклоняется, не подменяется 0/100.
3. Вторая перегонка: объём/крепость сырца, крепость продукта, доли голов и
   хвостов от абсолютного спирта. Вывод: АС, головы/хвосты **в литрах АС**,
   расчётный выход продукта. Реальный объём фракций зависит от их крепости,
   которой среди полей нет; потому литры АС прямо обозначены. Дополнительные
   потери не моделируются. Доли ≥100 % и нулевая крепость продукта отклоняются.

Данные вводятся вручную: датчики не подставляются автоматически, калькулятор
не меняет пороги, калибровку датчиков, звук, Wi-Fi, Google или выходы.

## Источники и точность

Код нелицензированного проекта samogon_calculator не копировался. Его поля
и предоставленные владельцем снимки использованы как описание нужных экранов.
Интерфейсы, проверки и баланс реализованы отдельно. Коэффициенты и порядок
полинома плотности адаптированы из **alcoholometry-core**, коммит
`bf65395a00814d61603ab1d679c84bf4511b3a5e`, MIT, David Platt (2023).
Лицензия сохранена в third_party/alcoholometry-core/LICENSE и заголовках
генерируемых C++/JS. Модель OIML R22, ограниченная областью применения.
Она не является сертификацией калькулятора или проверкой конкретного ареометра.

Используется double и ограниченная бисекция 48 итераций, без неограниченных
циклов. Математика C++/JS проверяется на одинаковых векторах. Коэффициенты
хранятся один раз в calculator/oiml-coefficients.json; генератор воспроизводит
C++-таблицу, браузерный файл и встроенные в APP offline-ресурсы.

## Управление

В веб-приложении: открыть «Калькулятор», выбрать расчёт, ввести значения.
Допускается десятичная запятая или точка. Неполные/неверные данные не создают
результат 0. Расчёт обновляется при вводе, есть кнопки «Рассчитать»/«Очистить».
Поля хранятся в отдельных ключах localStorage; прежние настройки не меняются.
После загрузки обновлённого PWA расчёты доступны и без Интернета.

На БУСА: LEFT/RIGHT → «Калькулятор»; UP/DOWN → вид расчёта; ENT → открыть.
UP/DOWN выбирают поле; ENT начинает ввод, цифры вводят число; удержание 0 более
2 секунд вводит запятую. ENT подтверждает; ESC отменяет. F1 очищает ввод,
а вне редактора очищает поля текущего расчёта. ESC возвращает в меню.
LEFT/RIGHT вне редактора сохраняют прежнее переключение разделов; в редакторе
двигают курсор. # и * остаются неназначенными. F2 вне редактора по-прежнему
гасит TFT. Поля TFT хранятся только в RAM, NVS не записывается.

Существующие индексы 0…6 сохранены, калькулятор добавлен под индексом 7.
Для корректной передачи номера экрана RainMaker диапазон прежнего параметра
расширен до 0…7 и обработчик допускает 7. Его старое имя «Раздел (0-6)»
сохранено для совместимости регистрации; остальные имена/типы/параметры не
изменены. Политика BLE, OTA и округление температур TELEM2 сохранены.

## Проверки и сборка

```
python3 -B ci/generate_calculator.py --check
python3 -B tests/test_calculator.py
python3 -B tests/test_calculator_keypad.py
python3 -B tests/test_rm_preservation.py
python3 -B tests/test_ble_ota.py
python3 -B tests/test_rm_tracker.py
python3 -B tests/test_rm_telemetry.py
python3 -B -m unittest discover -s tests -p test_firmware_contract.py -v
python3 -B tests/test_calculator_browser.py
BUSA_TEST_BROWSER=webkit python3 -B tests/test_calculator_browser.py
```

Browser tests требуют Playwright 1.56.0 и соответствующих Chromium/WebKit.
Проверка на HTTP fixture **не является испытанием ESP32**; мобильные размеры
не являются настоящими iPhone. WebKit на Linux не заменяет Safari на iOS.

Сборка: .github/workflows/busa-calculator.yml. CLI 1.3.1, ESP32 core 2.0.17,
библиотеки из TELEM2. Профиль ESP32-S3 N16R8, Flash16MB, PSRAM OPI,
штатная CSV-разметка с OTA-слотами по 3MiB.

```
python3 ci/generate_calculator.py
python3 ci/generate_google_ca.py --output firmware/BUSA_1M_WIFI_3v_GOOGLE/BUSA_GoogleCA.h
arduino-cli compile --clean --fqbn 'esp32:esp32:esp32s3:FlashSize=16M,PartitionScheme=app3M_fat9M_16MB,PSRAM=opi,CDCOnBoot=cdc,USBMode=hwcdc,FlashMode=qio,DebugLevel=none' --output-dir out firmware/BUSA_1M_WIFI_3v_GOOGLE
python3 ci/package_calculator.py --build-dir out --core-dir /path/to/esp32/2.0.17 --esptool /path/to/esptool_py/4.5.1/esptool.py
```

Генерируемые файлы уже включены в ZIP. В нём также есть исходные генераторы,
браузерные ресурсы, конфигурация, тесты и MIT license. Устаревший .ino.zip
не включён. Упаковщик проверяет image hash, chip ID, встроенную версию,
границы APP/USB, байтовый состав merged и неизменную разметку.

OTA BIN загружается в штатной панели 192.168.4.1 и не включает NVS/fctry.
Использовать его для действующего зарегистрированного устройства. Не выбирать
USB MERGED в OTA. USB с адреса 0x0 затрагивает обычный NVS и требует резервной
копии; сохранение настроек не гарантируется. Не выполнять erase-all для
сохранения RainMaker identity. Сохранение регистрации после реального OTA
на оборудовании новой версией ещё не проверялось.

## Онлайн и ограничения

Онлайн-страница сохраняет режим чтения телеметрии; вычисления не отправляются
контроллеру/Google/RainMaker. Service worker имеет новую версию кэша,
предварительно сохраняет калькулятор и не кэширует API. Автоперезагрузка при
обновлении уже установленного service worker убирает старый интерфейс без
очистки localStorage.

Отдельный workflow busa-calculator-online.yml публикует страницу через GitHub
Pages и проверяет наличие калькулятора и побайтовое совпадение опубликованного JS.
Публикация требует настроенного Pages и разрешённой ветки в github-pages
environment. Статус deployment, фактическая ссылка и результаты сборки
фиксируются отдельно в отчёте выпуска — наличие workflow не означает публикацию.

Остаётся физически проверить новый TFT-раздел/клавиатуру/ориентации,
читаемость на настоящем экране, iPhone Safari/PWA, сохранение регистрации после
OTA, отсутствие отката после RESET и длительную совместную работу модулей.
Выходы контроллера этой работой не включались и код калькулятора к ним не обращается.
