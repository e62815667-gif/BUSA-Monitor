# BUSA CALC4 WIFI1 UI5 — 06.11.2026

Основа: исходники CALC4 WIFI1 из проверенного архива; исходный коммит 56481db46de7da46897871c1ebf0a3cd411534c5.
Версия: 14v9-N16R8-RM-CALC4-WIFI1-UI5-20261106.

Локальное приложение: один BUSA MONITOR, без номера и повторного заголовка над «Вода»; дата и ЧЧ:ММ; температурные блоки без рамок/подложек; увеличенный прозрачный SVG аппарата вместо WebP; семь пунктов нижнего меню помещаются на экране.
На физическом TFT: последовательные разделы Главная → Температуры → Отбор → Графики → События → Настройки → Диагностика → Калькулятор. Температуры и Диагностика — вертикальные списки, выделение идёт сверху вниз. При входе в эти разделы и калькулятор выбирается первая строка. «Настройки», их вложенные страницы и клавиши сохранены.
SVG основан на существующем векторном рисунке BUSA-Monitor/online/busa-approved-rig.svg.
Распиновка, драйверы, NVS, RainMaker, BLE, Google, звуковые выходы, датчики, Wi-Fi, калькулятор, таблица разделов и локальная OTA сохранены.

## Два отдельных файла

- BUSA_N16R8_RM_CALC4_WIFI1_UI5_APP_OTA.bin — установить через локальную страницу обновления по Wi-Fi. Использовать этот файл для OTA, после обновления обновить страницу приложения.
- BUSA_N16R8_RM_CALC4_WIFI1_UI5_USB_MERGED.bin — ESP32-S3 N16R8, запись через USB по адресу 0x0. Не выбирать его в OTA-форме.

Предпочтительно OTA: сохраняется прежняя разметка и NVS. USB merged содержит bootloader, partitions, otadata и приложение, поэтому может перезаписать обычную NVS; для сохранения настроек использовать OTA. Полный erase не нужен. RainMaker factory-раздел 0x610000 не входит в компактный USB-образ.

## Сборка

Arduino CLI 1.3.1, немодифицированный ESP32 Arduino 2.0.17, xtensa-esp32s3-elf-gcc esp-2021r2-patch5-8.4.0. Библиотеки в версиях из .github/workflows/busa-calculator.yml.
Параметры ESP32-S3: FlashSize=16M, PartitionScheme=app3M_fat9M_16MB, PSRAM=opi, CDCOnBoot=cdc, USBMode=hwcdc, FlashMode=qio, DebugLevel=none.
В этой среде официальный core установлен вручную как пользовательская платформа espressif:esp32:esp32s3, с явными runtime.tools.xtensa-esp32s3-elf-gcc.path и runtime.tools.esptool_py.path. На стандартной установке Arduino CLI использовать esp32:esp32:esp32s3 с теми же параметрами.
Не генерировать заново BUSA_GoogleCA.h при повторении этой сборки: сохранён сертификат базового выпуска.
Пакетирование: python ci/package_ui5.py --build-dir <out> --core-dir <esp32-2.0.17> --esptool <esptool.py>.

## Проверки и ограничения

Сборка реальной прошивки и offline-проверка двух BIN: ESP32-S3, заголовки, checksum, validation hash, вместимость OTA-раздела и совпадение APP внутри USB.
Тесты браузера Chromium: пять ширин 320/390/393/430/768, три темы, отсутствие переполнения, все вкладки, один заголовок без номера, ЧЧ:ММ, прозрачные температуры и SVG. Регрессионные браузерные тесты Wi-Fi и калькуляторов.
Фактический C++ keypadAction исполняется с аппаратными заглушками: восемь разделов вперёд/назад, все подменю, ENT/ESC, сохранение поведения Настроек. BLE/OTA/Wi-Fi и калькулятор проверяются существующими регрессионными тестами. Геометрия TFT калькулятора проверена для двух ориентаций и трёх тем.
На физической ESP32 прошивка не устанавливалась. Проверки на ПК не подтверждают реальное качество TFT, Wi-Fi-связь и сохранность настроек после обновления на устройстве.
