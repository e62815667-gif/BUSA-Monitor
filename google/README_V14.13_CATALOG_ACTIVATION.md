# БУСА 14.13v — подключение каталога обновлений Google

Дата: 22.10.2026. Актуальная плата: **ESP32-S3 N8R2**, Flash 8 МБ.

## Что уже проверено

- Пользователь установил **БУСА 14.13v** через локальный APP OTA.
- Прямое чтение телеметрии из Google Sheet подтвердило `БУСА 1М WiFi 14v13-N8R2-OTA-DIAG`, HTTP 200 и не менее трёх подтверждённых отправок.
- Устройство сообщило два OTA-раздела по **3 342 336 байт** (active `0x10000`, next `0x340000`).
- До активации нового Google Apps Script `google.cloud_update.catalog_seen=false`, потому что ACK пока содержит подтверждение сохранения, но не метаданные выпуска. Это **не ошибка Wi-Fi/TLS**.

## Что сделано в GitHub

- Актуальный общедоступный каталог `main/online/releases.json` содержит **V14.13** с SHA-256 и параметрами N8R2, `remote_flash_enabled=false`.
- Скрипт приёмника подготовлен в отдельной ветке: [BUSA_GoogleSheets_Receiver.gs](https://github.com/e62815667-gif/BUSA-Monitor/blob/lab/busa-v14-13-google-catalog-activation/google/BUSA_GoogleSheets_Receiver.gs)
- Скрипт после подтверждения сохранения пакета будет отдавать `{"stored":true,"release":{...}}`, где метаданные версии читаются только из специальных Script Properties.
- Все существующие ключи `BUSA_TOKEN`, `BUSA_VIEW_TOKEN` и `BUSA_SPREADSHEET_ID` сохраняются. Не записывать ключи в GitHub или чат.
- Онлайн-приложение различает уже установленную версию, более новую версию и каталог старше устройства.

## Единственное действие владельца, необходимое для включения на Google

1. Открыть **существующую** Google Таблицу БУСА → **Расширения → Apps Script**. Это должен быть проект, который уже принимает измерения в лист `BUSA_telemetry`.
2. В редакторе скрипта заменить код приёмника на **сохранённую ветку** по ссылке выше. Не создавать новый проект и не трогать секреты в Script Properties.
3. Сохранить. В списке функций выполнить один раз **`setupBusaReadOnlyReleaseV1413`** от учётной записи владельца. Эта функция меняет только 5 публичных параметров релиза; она не перепрошивает ESP32, не меняет пароль Wi-Fi и не затрагивает токены.
4. **Развернуть → Управление развёртываниями → Изменить действующее развёртывание → Версия: Новая версия → Развернуть.** Сохранить прежний URL `/exec`, по которому уже работает БУСА. Не делиться этим URL вместе с ключами доступа.
5. После очередных отправок проверить `/api/status` или раздел «Обновления» внутреннего приложения:
   - `google.http = 200`, `google.sent` растёт;
   - `google.cloud_update.catalog_seen = true`;
   - `google.cloud_update.available_version = "V14.13"`;
   - `google.cloud_update.build_flash_bytes = 8388608`;
   - `ota_preflight.slot_available = true`;
   - `ota_preflight.candidate_fits_slot = true` (для текущего APP BIN 1 110 768 байт);
   - `remote_install_enabled = false` по-прежнему.

### Если связь с Google нарушится

Не сбрасывать ESP32 и не прошивать повторно. Вернуться к предыдущему развёртыванию Apps Script через **Управление развёртываниями** (сохранить прежний проект и URL), затем проверить `BUSA_TOKEN`, версию развёртывания и журнал выполнений Apps Script. Никогда не публиковать токены.

## Ограничения и следующий этап

**Это только приём метаданных каталога**, не автоматический или удалённый запуск прошивки. Установленная V14.13 не содержит защищённого cloud OTA-загрузчика. Полное удалённое OTA потребует отдельной последующей прошивки через локальный канал, подтверждения безопасности и испытаний восстановления. Релейные каналы K1–K4 остаются аппаратно неактивными.
